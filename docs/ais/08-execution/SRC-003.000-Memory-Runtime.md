## 2. Architecture Details

### 2.1 Context Engine (`src/core/context/`)

**Components:**
- `ContextEngine` — Main orchestrator: builds, updates, queries, snapshots, persists contexts
- `ContextBuilder` — Aggregates entries from registered `ContextSourceProvider` instances
- `ContextResolver` — Queries context by key, source, priority, tag, or custom predicate
- `ContextSerializer` — JSON round-trip serialization with validation
- `ContextSnapshotManager` — Point-in-time snapshots for rollback
- `ContextCache` — LRU cache (monotonic counter for reliable eviction ordering)
- `ContextLoader` — File-based persistence via pluggable `ContextStorageAdapter`
- `ContextPolicyManager` — Lifecycle policies: max size, max entries, TTL, priority, merge, eviction

**Context Sources:** Session, History, Knowledge, ExecutionState, Configuration, Runtime

**Policy Config:**
- `maxContextSizeBytes`: 10 MB default
- `maxEntriesPerContext`: 10,000 default
- `defaultTtlMs`: 1 hour
- `compressionThresholdBytes`: 1 MB
- `mergeConflictStrategy`: priority-wins | newest-wins | manual

**Eviction Algorithm:** Priority + Recency scoring. Expired entries get score -1 (evicted first). Non-expired: `score = (1000 - priority) + (age_in_seconds)`. Lowest score evicted first.

### 2.2 Memory Runtime (`src/core/memory/`)

**3-Tier Architecture (ADR-008.000):**

| Layer | Class | Scope | TTL | Persistence |
|-------|-------|-------|-----|-------------|
| Working | `WorkingMemory` | Per-execution | None | None (cleared on dispose) |
| Session | `SessionMemory` | Per-session | Optional | JSON serialization |
| Persistent | `PersistentMemory` | Cross-session | Optional | Pluggable `PersistentStorageAdapter` |

**MemoryRuntime Orchestrator:**
- Unified `store/retrieve/delete/query` API with `MemoryLayer` parameter
- Cross-layer queries via `MemoryQuery` (layer, keyPattern, sessionId, executionId, tag, minAccessCount)
- Aggregate stats across all layers
- Session isolation enforcement via `MemoryIsolationGuard`

**Isolation Rules:**
- Working: no sessionId required, no cross-session
- Session: sessionId required, no cross-session
- Persistent: no sessionId required, cross-session allowed

### 2.3 Session Runtime (`src/core/session/`)

**FSM States:** Created → Running → Paused → Running (resume) → Completed → Archived

**Key behaviors:**
- Each session owns an independent `TypedStateMachine<SessionState>`
- `autoPersist` flag: persist on every state transition
- `recordExecution()`: links sessions to pipeline executions
- FSM reconstruction on `loadSession()`: replays transitions to reach target state
- Serialization/Deserialization with branded type stripping

### 2.4 Checkpoint Engine (`src/core/checkpoint/`)

**Checkpoint captures:**
- `executionId`, `goalId`, `planId`, `stage`, `executionState`
- `variables`, `completedSteps`, `pendingSteps`
- `metadata`

**Auto-checkpoint stages:** planning, ready, step-completed, execution-completed

**Features:**
- `maxCheckpoints` enforcement with oldest-first purge
- `consumeCheckpoint()`: valid → consumed (single-use)
- `invalidateCheckpoint()`: valid → failed
- Deep defensive copies of variables and metadata
- Pluggable `CheckpointStorageAdapter` for persistence

### 2.5 Recovery Runtime (`src/core/recovery/`)

**Recovery Strategies:**

| Strategy | Steps | Requires Checkpoint |
|----------|-------|-------------------|
| `FullRecoveryStrategy` | load-session → restore-memory → restore-pipeline → prepare-continuation | Yes |
| `MemoryOnlyRecoveryStrategy` | load-session → restore-memory | No |
| `SessionOnlyRecoveryStrategy` | load-session | No |

**Recovery Flow:**
1. Select strategy based on available resources
2. Create `RecoveryPlan` with ordered steps
3. Execute steps sequentially, publishing events per step
4. On success: status → Ready, build `RestoredState`
5. On failure: status → Failed, error captured in plan

**Fallback:** FullRecoveryStrategy → MemoryOnlyRecoveryStrategy → SessionOnlyRecoveryStrategy

## 3. Design Principles Compliance

- **DR-02**: All cross-subsystem communication via EventBus (fire-and-forget)
- **DR-03**: Single MemoryRuntime per process, no global singleton
- **DR-07**: All persistence via pluggable adapters (ADR-004)
- **DR-08**: All public interfaces are TypeScript types
- **ADR-010**: Data flows within trust boundaries; no cross-zone memory leaks
- **ADR-012**: Minimal privilege — session isolation enforced at runtime
- **INV-012**: All domain events carry EventClassification

## 4. Integration Points

```
Execution Pipeline
  ├──→ ContextEngine (build context for execution)
  ├──→ SessionRuntime (create/track session)
  ├──→ MemoryRuntime (store/retrieve execution variables)
  ├──→ CheckpointEngine (checkpoint after each stage)
  └──→ RecoveryRuntime (recover from crash)
         ├──→ SessionRuntime (restore session)
         ├──→ MemoryRuntime (restore memory layers)
         └──→ CheckpointEngine (restore pipeline state)
```
