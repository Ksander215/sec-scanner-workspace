## 0. Overview

This manifest defines the Identity & Preference Runtime — the first subsystem that transforms AIS from a generic execution engine into a **personal intelligent platform**. The Identity Runtime manages who users are, what they prefer, how they make decisions, what they are permitted to do, and how they relate to organizations and teams.

### 0.1 Core Principle

> Identity does not know about medicine. Identity does not know about security. Identity does not know about law. Identity knows only: who the user is, what roles they hold, what preferences they have, how they make decisions, what they are permitted to do, and how they prefer to work.

All domain-specific knowledge arrives later through Domain Packs.

## 3. State Machine

### 3.1 Identity Lifecycle FSM

```
Created → Configured → Active
                          ↘ Suspended ↔ Active
Any non-terminal → Archived (terminal)
```

| From | To | Trigger |
|---|---|---|
| Created | Configured | Profile created |
| Configured | Active | Verification complete |
| Active | Suspended | Administrative action |
| Suspended | Active | Reinstatement |
| * | Archived | Deactivation |

### 3.2 FSM Transitions (9 total)

1. Created → Configured
2. Created → Archived
3. Configured → Active
4. Configured → Suspended
5. Configured → Archived
6. Active → Suspended
7. Active → Archived
8. Suspended → Active
9. Suspended → Archived

Invalid transitions are rejected by the `TypedStateMachine` with a clear error.

## 4. Preference Resolution Chain

Preferences are resolved in a hierarchical chain, from most specific to most general:

```
User → Organization → Team → System
```

When a preference is requested:
1. Check the identity's own preferences (User scope)
2. Check the organization's preferences (if member)
3. Check the team's preferences (if member)
4. Check system preferences (OwnerType.System identities)

The first match wins. Resolver cache tracks hit/miss ratio.

### 4.1 Preference Snapshot & History

- **Snapshots**: Point-in-time captures of all preferences. Enforced history limit.
- **History**: Versioned log of every preference change. Enforced entry limit.
- **Restore**: Reverts all preferences to a snapshot state.

---

## 5. Policy Resolution Chain

Policies are evaluated in a hierarchical chain, from least specific to most specific:

```
System → Organization → Team → Role → User → Session
```

### 5.1 Resolution Rules

1. Collect all applicable policies at each scope level
2. Sort by priority (highest first)
3. Evaluate rules: **Deny wins over Allow at the same priority level**
4. Return the first match with the highest effective priority

### 5.2 Scope Convention

| Scope | Pattern | Example |
|---|---|---|
| System | `System` | Global policy |
| Organization | `org:{orgId}` | Organization-specific |
| Team | `team:{teamId}` | Team-specific |
| Role | `role:{roleId}` | Role-specific |
| User | `user:{identityId}` | User-specific |
| Session | `session:{identityId}` | Session-specific |

|---|---|---|

| `PreferenceChanged` | StateChange | Preference value changed |
| `PreferenceResolved` | Result | Preference resolved via chain |
| `PreferenceSnapshotCreated` | Action | Snapshot created |
| `PreferenceRestored` | StateChange | Snapshot restored |
| `OrganizationCreated` | Action | Organization created |
| `TeamCreated` | Action | Team created |
| `RoleAssigned` | Action | Role assigned to identity |
| `RoleRevoked` | Action | Role revoked from identity |
