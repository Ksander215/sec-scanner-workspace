### 3.2 What Is NOT Frozen

The following are not part of this baseline and may evolve independently:

- Implementation code, test suites, and build artefacts
- TypeScript type definitions (implementation of domain model)
- Operational runbooks and deployment configurations
- Plugin implementations and third-party extensions
- Provider-specific configurations and credentials
- Governance operating procedures (GOV documents)
- Additional ADRs and DADRs created post-baseline

## 6. Maintenance Rules

### 6.1 Change Control

Any modification to the domain baseline requires:

1. **Formal Change Request** submitted per GOV-003.000
2. **Impact Analysis** covering affected entities, aggregates, invariants, events, and consumers
3. **DADR** (Domain Architecture Decision Record) for domain-internal changes, or **ADR** for cross-domain changes
4. **Domain Governance Review** per GOV-004.000
5. **New Baseline Declaration** (BAS-002.001 or later) with updated version

### 6.2 Severity Classification

Changes are classified per GOV-004.000 severity levels:

| Change Type | Severity | Example | Approval Authority |
|---|---|---|---|
| Entity removal | S1 | Remove TrustScore | Domain Owner + Architecture Board |
| Aggregate restructuring | S1 | Merge User and Trust | Domain Owner + Architecture Board |
| New entity addition | S2 | Add FeatureFlag | Domain Owner + Architecture Review |
| New invariant | S2 | Add INV-015 | Domain Owner + Architecture Review |
| Attribute modification | S3 | Add optional field | Domain Owner |
| New domain event | S3 | Add PluginUpdated | Domain Owner |
| Relationship update | S4 | Cardinality change | Domain Owner |
| Documentation fix | S5 | Typo correction | Domain Owner |

### 6.3 Prohibited Actions

The following actions are FORBIDDEN without a new baseline version:

- Adding or removing domain entities without a DADR
- Modifying aggregate boundaries without Architecture Board approval
- Changing invariant set without severity S1+ change request
- Creating domain events without registered producer and consumer
- Modifying ubiquitous language without UL version increment
