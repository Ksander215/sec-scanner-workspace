## 0. Preamble

This Constitution is the highest normative document of the Adaptive Intelligence System (AIS) programme. It defines the inalienable principles, immutable laws, and the decision framework that governs every subsequent architectural, domain, governance, and implementation choice.

Any document of lower tier (ARC, DOM, ADR, SEC, GOV, implementation artefacts) MUST be consistent with this Constitution. In the case of conflict, the Constitution prevails. Modification of this Constitution requires a Constituent Convention and is permitted only under the procedure defined in §13.

AIS is not a chatbot. AIS is not a widget. AIS is not a FAQ engine. AIS is an operating system of interaction between the platform and its human operators, in which assistance finds the user before the user looks for it.

## 1. Constitutional Principles (CP)

The 23 Constitutional Principles form the value system of AIS. They are not negotiable, not tradeable, and not subject to architectural convenience.

### CP-001 — Assistance Finds the User
The system proactively surfaces help at the moment and in the form the user actually needs it. The user never has to hunt for help that should already be obvious from context.

### CP-002 — Context Is the Substrate
Every recommendation, notification, and action is grounded in observable context: current page, recent actions, role, environment state. Context-free advice is forbidden.

### CP-003 — Confidence Is Explicit
Every recommendation carries an explicit confidence level. Recommendations are presented differently at Very Low, Low, Moderate, High, and Very High confidence. The system never hides its uncertainty.

### CP-004 — Trust Is Earned, Never Demanded
Trust is built through observable behaviour, transparent confidence scoring, and respect for the user's attention. The system never asks the user to "just trust it".

### CP-005 — Local Sovereignty
The user's machine, browser, and workspace are sovereign territory. AIS enters them only through consent and only to the extent necessary for the requested assistance.

### CP-006 — Minimal Surface
The system shows the smallest possible surface required to deliver value. Notifications are short, panels are narrow, interruptions are scarce. Less is more.

### CP-007 — Memory Is Adaptive
The system remembers what the user did, what they dismissed, what they read slowly, what they ignored — and adapts. Forgetting is also a feature.

### CP-008 — Sound Identity
Where sound is used, it is unique, brief, identifiable, and never borrowed from another product. Sound is a brand asset, not an alarm.

### CP-009 — Role-Aware Narrative
The same fact is told differently to a CEO, a DevOps engineer, a security analyst, and a developer. Narrative is a function of role.

### CP-010 — No Fear, No Alarm
The vocabulary of AIS excludes fear-based words ("danger", "critical error", "urgent") except where there is genuine, immediate, physical-or-data risk. The system informs, it does not frighten.

### CP-011 — Honour User Dismissal
When the user dismisses a notification, the system treats it as information. Dismissal is data. Repetition of a dismissed tip is forbidden unless context has materially changed.

### CP-012 — Adaptive Lifetime
Notification lifetime is not fixed. It adapts to the user's observed reading speed. Fast readers get short notifications; slow readers get longer ones; users who always read in full get manual-close mode.

### CP-013 — Composition over Coupling
AIS is composed of cooperating modules with explicit boundaries. Cross-module coupling through private internals is forbidden. Public contracts are the only permitted surface.

### CP-014 — Provider Neutrality
AIS is independent of any specific LLM provider, scanner provider, or storage provider. Providers are pluggable. Lock-in is forbidden.

### CP-015 — Traceable Decisions
Every architectural decision is recorded in an ADR. Every domain decision is recorded in a DADR. Every deviation is recorded with rationale. There are no undocumented choices.

### CP-016 — Read-Only Foundation
The constitutional, architectural, and domain layers are read-only relative to implementation pressure. Implementation may surface issues; it may not silently rewrite the foundation.

### CP-017 — Single Source of Truth
Each fact about AIS exists in exactly one canonical location. Other documents reference it. Duplication is a defect.

### CP-018 — Versioned Evolution
Every document carries an explicit version. Baselines are immutable snapshots. Evolution proceeds through controlled mutation, never through silent edits.

### CP-019 — Proportionate Response
The form of a notification matches its content. A small observation is a small card. A significant finding gets a richer surface. The medium respects the message.

### CP-020 — Accessibility by Default
AIS is accessible: keyboard-navigable, screen-reader-friendly, motion-respecting, and contrast-compliant. Accessibility is not a feature; it is a precondition.

### CP-021 — Privacy of Profile
The behavioural profile (memory, role, goals) belongs to the user. It is not shared, not sold, not used for cross-user analytics without explicit, granular consent.

### CP-022 — Telemetry Is Honest
When the system collects telemetry, it says so, says what, and says why. Covert telemetry is forbidden. Telemetry is opt-out where regulation requires and opt-in elsewhere.

### CP-023 — Exit Is Always Possible
The user can disable AIS, mute it, downgrade its autonomy level, or export its memory and leave. The exit door is always open and never penalised.

## 2. Architectural Laws (AL)

Architectural Laws translate the Constitutional Principles into binding architectural constraints. Violation of an AL is a defect, regardless of whether the system still functions.

### AL-001 — Layered Authority
Documents are organised in tiers: CON (L1) > ARC/DOM (L2) > ADR/DADR (L3) > SEC (L4) > GOV (L5) > Implementation (L6). A lower tier MUST NOT contradict a higher tier.

### AL-002 — Boundary by Contract
Module-to-module interaction is permitted only through published contracts. Contracts are versioned. Breaking changes require a new contract version and a deprecation path.

### AL-003 — No Silent Override
No subsystem may override the autonomy level, confidence level, or notification policy set by another subsystem without going through the unified AIS controller.

### AL-004 — One Memory, One Authority
There is exactly one Adaptive Memory Engine per session. All other modules read from it through its public API. Private copies of behavioural state are forbidden.

### AL-005 — Provider behind Abstraction
Every external provider (LLM, scanner, storage, embedding) sits behind an interface owned by AIS. The interface is the boundary; the provider is interchangeable.

### AL-006 — Trust Zones Are Explicit
The system is partitioned into Trust Zones Z0–Z4. Data and execution flow between zones only through declared, audited gates. Zone escalation without a gate is forbidden.

### AL-007 — Autonomy Is a Spectrum
AIS operates on an Autonomy Spectrum of five levels: Observe, Suggest, Act-on-Approval, Act-and-Report, Autonomous. The current level is user-controllable and known to the system at all times.

### AL-008 — Events Are the Spine
Cross-module coordination uses the Event Bus. Direct method calls across module boundaries are forbidden outside the AIS controller itself.

### AL-009 — File Is the Unit of Storage
All persisted artefacts (reports, evidence, memory snapshots, plugin manifests) are files with stable paths. Opaque blobs without a path are forbidden.

### AL-010 — TypeScript Is the Contract Language
All contracts within the AIS core are expressed in TypeScript types. Runtime is responsible for upholding what the types declare.

### AL-011 — Plugins Cannot Escalate
Plugins operate inside Trust Zone Z2 by default. They cannot elevate themselves, cannot read outside their declared scope, and cannot subscribe to events above their declared classification.

### AL-012 — Decisions Are Auditable
Every state change with side effects outside the AIS core is logged with actor, intent, before-state, after-state, and rationale. The audit log is append-only.

## 3. Decision Framework

The Constitution defines a 9-level decision framework that maps each kind of question to the authority responsible for resolving it.

| Level | Question kind | Authority | Output |
|-------|---------------|-----------|--------|
| D1 | Is this question about values or invariants? | Constitution | CP / AL |
| D2 | Is this question about system shape or boundaries? | Architecture | ARC / FP / DR |
| D3 | Is this question about the problem domain? | Domain | DOM / DP / INV |
| D4 | Is this question about a single design decision? | ADR | ADR record |
| D5 | Is this question about a domain design decision? | DADR | DADR record |
| D6 | Is this question about security controls? | Security | SEC |
| D7 | Is this question about governance process? | Governance | GOV |
| D8 | Is this question about implementation? | Implementation | Code + tests |
| D9 | Is this question about operation? | Operations | Runbook |

A decision is valid only when resolved at the correct level. Resolving an L1 question at L8 is a defect, even if the answer happens to be correct.

## 4. Authority and Delegation

The Constitution delegates authority as follows:

- **Constituent Convention** — sole authority to amend CON-001.
- **Architecture Council** — authority to issue and amend ARC and to ratify ADRs.
- **Domain Council** — authority to issue and amend DOM and to ratify DADRs.
- **Security Council** — authority to issue and amend SEC.
- **Governance Council** — authority to issue and amend GOV.
- **Implementation Teams** — authority over implementation artefacts within the constraints of higher tiers.

All authorities are accountable to the Constitution.

---

## 5. Conflict Resolution

When two documents conflict:

1. The higher tier prevails.
2. If same tier, the more recent version prevails, unless the older document is explicitly marked as authoritative for the matter in question.
3. If conflict cannot be resolved by tier or version, the Architecture Council adjudicates.
4. The adjudication is recorded as an ADR and the loser document is amended or deprecated.
