## 3. Aggregate Design

Aggregates define consistency boundaries. All mutations to members within an aggregate must go through the aggregate root to enforce invariants. Cross-aggregate communication is achieved exclusively through domain events.

### 3.1 User Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | UserProfile                                            |
| **Members**     | UserProfile, UserAction, ReadingSpeed, NavigationSpeed, UserRole, SessionContext |
| **Boundary**    | All entities related to a single user's identity, behavioural patterns, and session state. |
| **Invariants**  | INV-001 (one profile per session), INV-014 (no session without context) |
| **Entry Point** | `UserProfile.recordAction(action)`                      |
| **Notes**       | SessionContext is included to enforce the invariant that every session belongs to a user. Cross-reference to TrustScore is handled via the Trust Aggregate. |

### 3.2 Intelligence Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | ConfidenceResult                                       |
| **Members**     | ConfidenceResult, ConfidenceLevel, AISPrediction      |
| **Boundary**    | All entities related to confidence assessment, classification, and prediction generation. |
| **Invariants**  | INV-002 (confidence in [0, 100]), INV-011 (narrative requires role) |
| **Entry Point** | `ConfidenceResult.calculate(prediction, role)`        |
| **Notes**       | AISPrediction is a member to ensure prediction-confidence consistency. Predictions without a confidence result are incomplete. |

### 3.3 Communication Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | AISNotification                                        |
| **Members**     | AISNotification, NotificationType, NotificationLifetime, FrequencyMode, LifetimePolicy |
| **Boundary**    | All entities related to notification creation, adaptive delivery, and lifecycle management. |
| **Invariants**  | INV-004 (no notification without type), INV-010 (no tip repetition without context change) |
| **Entry Point** | `AISNotification.create(type, content, profile, confidenceResult)` |
| **Notes**       | FrequencyMode and LifetimePolicy are embedded to enforce notification proportionality (DP-007). |

### 3.4 Provider Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | ProviderInfo                                          |
| **Members**     | ProviderInfo, ProviderType                            |
| **Boundary**    | All entities related to external provider abstraction and health management. |
| **Invariants**  | INV-006 (no access without credentials)               |
| **Entry Point** | `ProviderInfo.register(type, name, endpoint, credentials)` |
| **Notes**       | ProviderType is embedded as a Value Object. Health checks and capability resolution happen within this boundary. |

### 3.5 Plugin Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | PluginManifest                                        |
| **Members**     | PluginManifest, PluginPermission                       |
| **Boundary**    | All entities related to plugin declaration, permission scoping, and trust zone assignment. |
| **Invariants**  | INV-005 (no run without manifest), INV-013 (no permission beyond scope) |
| **Entry Point** | `PluginManifest.register(pluginName, capabilities, permissions, trustZone)` |
| **Notes**       | Permissions are exclusively defined within the manifest. Runtime enforcement happens at the aggregate root. |

### 3.6 Trust Aggregate

| Property        | Value                                                  |
|-----------------|--------------------------------------------------------|
| **Root Entity** | TrustScore                                            |
| **Members**     | TrustScore, TrustFactor                               |
| **Boundary**    | All entities related to trust assessment, factor accumulation, and scoring. |
| **Invariants**  | INV-007 (cross-zone gate check), INV-008 (action within autonomy), INV-009 (audit with actor and intent) |
| **Entry Point** | `TrustScore.recalculate(factors[], previousScore)`     |
| **Notes**       | TrustFactors are added to the score via the root. All trust-sensitive operations (cross-zone data flow, autonomy escalation) must query the TrustScore. |

## 4. State Machines

Each stateful entity is governed by a finite state machine (FSM). Transitions are triggered by domain events or time-based conditions. Invalid transitions must be rejected at the aggregate root.

### 4.1 UserProfile FSM

```
  ┌──────────────┐
  │ Initializing │ ← Entry point: profile created, no actions recorded
  └──────┬───────┘
         │ first action recorded
         ▼
  ┌──────────────┐     inactivity threshold       ┌───────────┐
  │    Active    │ ──────────────────────────────→ │ Suspended │
  └──────┬───────┘                                └─────┬─────┘
         │                                         new session │
         │                              ┌──────────────────────┘
         │  ←─────────────────────────  │
         │                              ▼
         │ ←──────────────────  ┌───────────┐
         │    reactivation?     │  Archived  │ ← Terminal state: permanent retention
         └────────────────────→ └───────────┘    no further mutations allowed
```

| State        | Entry Condition              | Exit Conditions           | Allowed Operations                    |
|--------------|------------------------------|---------------------------|---------------------------------------|
| Initializing | Profile created              | First action recorded     | Seed default values, no predictions  |
| Active       | First action recorded        | Inactivity / archive      | Record actions, generate predictions  |
| Suspended    | Inactivity timeout exceeded  | New session / archive     | No actions accepted, no notifications |
| Archived     | Explicit archive command     | None (terminal)            | Read-only audit access                |

### 4.2 AISNotification FSM

```
  ┌─────────┐
  │ Created │ ← Entry point: notification instantiated
  └────┬────┘
       │ display conditions met
       ▼
  ┌──────────┐
  │ Displayed│ ← Visible to user; lifetime timer active
  └──┬───┬───┘
     │   │
     │   └─── lifetime elapsed ──→ ┌─────────┐
     │                            │ Expired  │ ← Terminal: no user interaction
     │                            └─────────┘
     │
     └─── user closes ──→ ┌──────────┐
                         │ Dismissed │ ← Terminal: DP-004 (dismissal is data)
                         └──────────┘

  ┌──────────┐
  │ Displayed│
  └────┬─────┘
       │ user clicks / engages
       ▼
  ┌───────────┐
  │ ActedUpon │ ← Terminal: interaction recorded for profile enrichment
  └───────────┘
```

| State      | Entry Condition            | Exit Conditions             | Allowed Operations               |
|------------|----------------------------|-----------------------------|-----------------------------------|
| Created    | Notification instantiated   | Display conditions met      | Content adjustment, priority set  |
| Displayed  | Rendered to user            | Dismiss / Expire / ActUpon  | Timer countdown, content display  |
| Dismissed  | User explicitly closed       | None (terminal)             | Record dismissal as UserAction    |
| Expired    | Lifetime elapsed            | None (terminal)             | Record expiry event for audit     |
| ActedUpon  | User engaged with content    | None (terminal)             | Record engagement as UserAction   |

### 4.3 SessionContext FSM

```
  ┌──────────────┐
  │ Initializing │ ← Entry point: session started, context being populated
  └──────┬───────┘
         │ context population complete
         ▼
  ┌──────────────┐     user logout / timeout / system shutdown
  │    Active     │ ─────────────────────────────────────────────→ ┌───────┐
  └──────────────┘                                              │ Ended │ ← Terminal
                                                               └───────┘
```

| State        | Entry Condition           | Exit Conditions             | Allowed Operations                |
|--------------|---------------------------|-----------------------------|-----------------------------------|
| Initializing | Session started           | Context population complete | Load profile snapshot, set env    |
| Active       | Context ready             | Logout / timeout / shutdown  | Accumulate state, serve queries   |
| Ended        | Session terminated        | None (terminal)             | Read-only, frozen for audit       |

### 4.4 ConfidenceResult FSM

```
  ┌────────────┐
  │ Calculated │ ← Entry point: score computed, level assigned, narrative generated
  └─────┬──────┘
        │ associated notification displayed
        ▼
  ┌───────────┐     session ended or superseded
  │ Presented │ ───────────────────────────────→ ┌─────────┐
  └───────────┘                                │ Archived │ ← Terminal
                                               └─────────┘
```

| State      | Entry Condition             | Exit Conditions          | Allowed Operations              |
|------------|-----------------------------|--------------------------|---------------------------------|
| Calculated | Score computed              | Notification presented    | Narrator formatting, level check|
| Presented  | Shown to user               | Session end / superseded  | Read access, audit reference    |
| Archived   | Session ended / superseded  | None (terminal)          | Read-only, model training input |

## 5. Value Objects

Value objects are immutable constructs with no identity. Equality is determined by comparing their constituent values. They are always owned by an entity and embedded within it.

### 5.1 ConfidenceLevel

| Property       | Value                                                       |
|----------------|-------------------------------------------------------------|
| Allowed Values | `Very Low`, `Low`, `Moderate`, `High`, `Very High`         |
| Mapping        | [0–20) → Very Low; [20–40) → Low; [40–60) → Moderate; [60–80) → High; [80–100] → Very High |
| Description    | Maps numeric confidence scores to human-readable presentation tiers. Drives narrative depth and notification urgency (DP-002). |

### 5.2 UserRole

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `CEO`, `DevOps`, `Engineer`, `Analyst`  |
| Description    | Classifies the user's organisational function. Determines narrative style, data granularity, and notification priority (DP-006). CEO sees strategic summaries; Engineer sees technical detail. |

### 5.3 AutonomyLevel

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `L0`, `L1`, `L2`, `L3`, `L4`            |
| Description    | Controls system action authority. L0 = fully manual (suggestions only); L1 = assisted (auto-prepare, manual approve); L2 = supervised (auto-execute with review); L3 = semi-autonomous (auto-execute, notify on failure); L4 = fully autonomous. Enforced by INV-003 (DP-014). |

### 5.4 TrustZone

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `Z0`, `Z1`, `Z2`, `Z3`, `Z4`            |
| Description    | Bounded region for data flow control. Z0 = most trusted (core system); Z4 = least trusted (external plugins). Cross-zone data flow requires gate check per INV-007. |

### 5.5 ReadingSpeed

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `fast`, `normal`, `slow`                |
| Description    | Observed text consumption rate classification. Derived from user interaction telemetry (words per minute, scroll velocity). Influences notification lifetime (DP-012). `fast` → shorter lifetime; `slow` → longer lifetime. |

### 5.6 NavigationSpeed

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `fast`, `normal`, `slow`                |
| Description    | Observed interface movement rate classification. Derived from clicks per minute and page transition frequency. Influences prediction timing and notification pacing. |

### 5.7 FrequencyMode

| Property       | Value                                    |
|----------------|------------------------------------------|
| Allowed Values | `rare`, `normal`, `frequent`            |
| Description    | Controls notification cadence per user. Adaptively assigned based on dismissal history (DP-013). `rare` = max 2 per session, long cooldown; `normal` = max 5 per session; `frequent` = max 10 per session, short cooldown. |

### 5.8 NotificationType

| Property       | Value                                                      |
|----------------|------------------------------------------------------------|
| Allowed Values | `info`, `success`, `warning`, `error`, `tip`, `achievement` |
| Description    | Semantic classification for visual treatment. Determines persistence policy, colour scheme, and sound cue (DP-007, DP-011). `error` → persistent banner + alert sound; `tip` → transient toast + soft chime. |

### 5.9 EventClassification

| Property       | Value                                                  |
|----------------|--------------------------------------------------------|
| Allowed Values | `info`, `action`, `result`, `error`, `state-change`  |
| Description    | Categorises domain events for routing and audit. All events must carry a classification per INV-012. `action` = user-initiated; `result` = system-computed; `state-change` = lifecycle transition. |

## 6. Domain Events

Domain events represent facts about state changes that have already occurred. They are immutable, carry a timestamp, and are the sole mechanism for cross-aggregate communication.

### 6.1 UserActionRecorded

| Property   | Value                                                                |
|------------|----------------------------------------------------------------------|
| **Producer** | User Aggregate (UserProfile)                                        |
| **Consumer** | User Aggregate (profile update), Trust Aggregate (factor generation) |
| **Payload** | `{ actionId, profileId, actionType, target, timestamp, classification }` |
