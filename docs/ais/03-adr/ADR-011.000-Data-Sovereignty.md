# ADR-011: Data Sovereignty

**Version:** 000
**Status:** ACCEPTED
**Date:** 2025-01-01
**Owner:** AIS Architecture

---

## Context

User data is central to the AIS experience. The system learns from user behaviour, preferences, goals, and interactions to provide personalised assistance. This creates a significant responsibility: the data that makes the AIS useful also represents a detailed portrait of the user.

Several concerns motivated this decision:

- **User trust:** Users will not engage with a system that exploits their data. The AIS must demonstrate that user data is treated as the user's property, not the platform's asset.

- **Regulatory compliance:** Data protection regulations (GDPR, CCPA, and similar frameworks) establish rights over personal data. The AIS must meet or exceed these standards by design.

- **Cross-user integrity:** Data from one user must never be used to benefit another user without explicit consent. The AIS must not perform cross-user behavioural analysis.

- **Data portability:** Users must be able to take their data with them if they choose to leave the platform.

The alternative of treating user data as a platform asset was rejected as it contradicts the constitutional principles (CP-005 Privacy, CP-021 Data Rights) and would undermine the trust relationship essential to the AIS's function.

## Decision

Establish a **Data Sovereignty** model with the following principles:

1. **User ownership:** All behavioural data generated by the AIS — including user profile, role definitions, goals, session memory, interaction history, and preference models — belongs to the user. The platform has custody, not ownership.

2. **No sharing without consent:** User data is not shared with third parties, not sold, and not used for cross-user analysis without explicit, informed user consent. Consent must be granular (per data type, per purpose) and revocable.

3. **Export right:** Users can export all their data in a standard, machine-readable format at any time. The export must include all data types: profile, memory, history, preferences, and any derived models.

4. **Deletion right:** Users can request full deletion of their data. Deletion must be comprehensive — not just anonymisation but actual removal from all storage, backups, and derived models.

5. **Honours CP-005 and CP-021:** This ADR is the operational expression of constitutional principles CP-005 (Privacy) and CP-021 (Data Rights).

## Consequences

### Positive

- **Strong privacy by design:** Data sovereignty is not an add-on but a foundational principle that shapes all system design decisions.

- **User trust:** Clear data ownership and control builds the trust necessary for users to engage deeply with the AIS.

- **Regulatory alignment:** The sovereignty model naturally aligns with GDPR, CCPA, and similar frameworks, reducing compliance risk.

- **Competitive differentiation:** In a market where data exploitation is common, a genuine data sovereignty model is a meaningful differentiator.

### Negative

- **Limits platform-side analytics:** The prohibition on cross-user analysis means the platform cannot derive aggregate insights from user data without consent. This limits the platform's ability to improve its service through data-driven optimisation.

- **Export/delete requires data portability design:** The export and deletion rights require careful data architecture to ensure all data is traceable, portable, and fully removable. This adds design and implementation overhead.

- **Consent management complexity:** Granular consent management requires a consent tracking system that records what the user has consented to, when, and for what purpose.

- **CP-021 (Data Rights):** This ADR is the primary operational mechanism for CP-021.
- **CP-003 (User Control):** Data sovereignty reinforces user control over their AIS experience.
