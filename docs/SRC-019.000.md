# TASK-AIS-011A.000 — AIS Companion Runtime

## Overview
AIS Companion is the first native product layer that orchestrates 16 subsystems to deliver
a unified AI companion experience. It integrates with existing Cognitive, Personal,
Workflow, Capability, Marketplace, and Knowledge runtimes without duplicating logic.

## Architecture
- **CompanionRuntime**: Main orchestrator coordinating all 16 subsystems
- **UserWorkspaceManager**: User workspace CRUD with limit enforcement
- **ConversationCenter**: Multi-conversation management with message limits
- **GoalCenter**: Goal lifecycle (Draft → Active → Completed) with priority tracking and analytics callbacks
- **DailyPlanner**: Daily plan creation, task management, and completion tracking
- **SolutionCenter**: Solution lifecycle with blueprint assembly, validation, and analytics callbacks
- **WorkflowDashboard**: Workflow visibility by session and solution
- **CapabilityManager**: Installed capability instance management
- **MarketplaceCenter**: Marketplace browsing, installation integration, and seed listings
- **KnowledgeCenter**: Knowledge base with category-based organization and search
- **AIControlCenter**: Autonomy level management with change history
- **InsightEngine**: Insight generation with type classification, confidence scoring, and analytics callbacks
- **NotificationCenter**: Notification lifecycle with priority and read tracking
- **AnalyticsDashboard**: Session, section, goal, solution, and insight metrics
- **ExplainabilityCenter**: Explainable AI — every recommendation answers Why/What value/What constraint/What alternatives
- **ValueOptimizationEngine**: Value scoring and optimization for goals, solutions, and insights with analytics callbacks
- **LifecycleManager**: FSM-based state machine for companion lifecycle

## Key Patterns
- Map-based internal state with frozen immutable entities
- Event-driven with InProcessEventBus integration
- Constructor(config, eventBus?) pattern
- Branded type IDs for type safety
- Explainable AI: every recommendation answers Why/What value/What constraint/What alternatives
- PHI-007: Never use `name` as field in error classes

## Dependencies
- **Analytics callbacks**: GoalCenter, SolutionCenter, InsightEngine, and ValueOptimizationEngine accept optional `analytics` callback parameter in constructors, wiring telemetry into the AnalyticsDashboard

## Key Interfaces
- **IAnalyticsDashboard**: `recordGoalCreated`, `recordRecommendationCreated`, `incrementSessions`, `decrementActiveSessions`, `recordSessionDuration`
- **IWorkflowDashboard**: `register` (register a workflow for tracking)
- **IMarketplaceCenter**: `seedListings` (populate initial marketplace data)
- **CompanionGoal**: includes `completedAt?: string` field for completion timestamp

## Desktop Screens (12 total)
All 12 Desktop screens are registered via `DesktopScreen` enum:
Workspace, Conversation, Planner, Goals, Solutions, Knowledge, Capabilities,
Marketplace, Notifications, Insights, Analytics, AI-Control
