## Overview

The Capability Runtime enables AIS to load, validate, activate, and manage domain-specific Capability Packs without modifying the core. After this task, the AIS core knows nothing about specific domains (Security, Medicine, Law, etc.) — it only knows how to load and manage Capability Packs.

## Architecture

```
AIS Core
├── Execution Runtime
├── Memory Runtime
├── Knowledge Runtime
├── Identity Runtime
├── Tool Runtime
│
└── Capability Runtime (NEW)
    ├── Capability Registry
    ├── Capability Validator
    ├── Dependency Resolver
    ├── Compatibility Checker
    ├── Capability Sandbox
    ├── Capability Metrics
    ├── Persistence Adapters
    └── Pack Lifecycle FSM
         │
         ▼
    Domain Pack SDK
    ├── CapabilityBuilder
    ├── createContract()
    ├── createManifestJson()
    └── PackGenerator
```

## Key Design Decisions

1. **No circular dependencies**: Capability Runtime depends only on core types, FSM, and EventBus.
2. **Immutable DTOs**: All domain objects use `Object.freeze()` and `readonly` properties.
3. **Result-free errors**: Capability Runtime throws errors (not Result pattern) — consistent with Tool Runtime.
4. **Fire-and-forget events**: Following ADR-002, event publishing never disrupts operations.
5. **Sandbox isolation**: Each pack gets its own context with permission-gated access to core resources.
6. **Dependency injection**: All components receive config via constructor, no singletons or global state.
7. **ESM + .js extensions**: Full Node16 module resolution compatibility.

## Compliance

## Integration Points

- **EventBus**: Publishes 12 event types via existing InProcessEventBus
- **FSM Framework**: Uses existing TypedStateMachine<S>
- **Service Interface**: CapabilityRuntime can be registered with Runtime as a Service
- **Persistence**: Pluggable adapters (InMemory default, File, Snapshot)
