# Session Invalid Conditions — Quick Reference

A session is **INVALID** and must be excluded from analysis if ANY of the following occur:

| # | Condition | Action |
|---|---|---|
| 1 | Participant received the correct answer before or during baseline | Discard entire session |
| 2 | Baseline phase was skipped | Discard entire session |
| 3 | AIS was used before baseline | Discard entire session |
| 4 | Observer provided hints about architecture | Discard entire session (observer error) |
| 5 | Question was changed after session started | Discard if change affected difficulty |
| 6 | Repository scope was changed during session | Discard if scope was narrowed/expanded |
| 7 | AIS was unavailable for a significant portion (>5 min) of AIS phase | Mark as partial; exclude from time analysis |
| 8 | Evidence was lost (recording failure, notes lost) | Exclude from qualitative analysis |

---

## Partial Validity

If only condition 7 or 8 applies, the session may be:
- **Included** for scoring dimensions that were captured
- **Excluded** from dimensions where evidence is incomplete
- **Marked** with a note explaining the limitation

## Observer Errors

If the observer made a protocol error (e.g., gave a hint):
1. Document the error precisely
2. Document what was said/hinted
3. Assess whether it affected the participant's understanding
4. If it materially affected the baseline → INVALID
5. If it was minor → note it and include with annotation

---

## Participant Behavior Issues

The following do NOT invalidate a session:
- Participant giving up early (score as incomplete baseline)
- Participant being very fast (record actual time)
- Participant being very slow (timebox at 45 min)
- Participant expressing frustration
- Participant disliking the tool

These are **data**, not errors.
