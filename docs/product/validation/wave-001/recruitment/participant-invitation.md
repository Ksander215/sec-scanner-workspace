## Invitation Text (Russian)

```
Здравствуйте!

Мы проводим исследование процесса анализа программного проекта и хотим
сравнить несколько способов решения архитектурной задачи.

Что потребуется:
- Исследовать незнакомую кодовую базу (~73k LOC, TypeScript)
- Ответить на вопрос об архитектуре системы
- Использовать инструмент для анализа (будет предоставлен на месте)
- Проверить полученные результаты по исходному коду

Время: 90–120 минут
Формат: индивидуальная сессия (онлайн или очно)

Ваши данные будут анонимизированы. Оценивается инструмент, а не вы.

Если вы готовы участвовать или хотите узнать больше — ответьте на это письмо.

Спасибо!
```

## Invitation Text (English)

```
Hello!

We are conducting research on the process of analyzing a software project
and would like to compare different approaches to solving an architecture
task.

What you'll do:
- Explore an unfamiliar codebase (~73k LOC, TypeScript)
- Answer a question about the system's architecture
- Use an analysis tool (provided during the session)
- Verify the results against the source code

Time commitment: 90–120 minutes
Format: Individual session (online or in-person)

Your data will be anonymized. We are evaluating the tool, not you.

If you're interested or want to learn more — please reply to this message.

Thank you!
```

---

## Key Framing Rules

### ALLOWED

- "Research on software architecture analysis process"
- "Compare different approaches to solving an architecture task"
- "Evaluate an analysis tool"
- "We are studying how people understand unfamiliar codebases"

### FORBIDDEN

- "We are testing an AI that helps you understand architecture faster"
- "Our AI assistant will help you"
- "We want to prove our tool is useful"
- "AIS provides contextual advantage over manual exploration"
- Any mention of expected outcome or hypothesis

---

## Distribution Channels

| Channel | Notes |
|---|---|
| Direct message to known contacts | Preferred — higher response rate |
| Professional community (Telegram/Discord) | Acceptable if neutral framing is maintained |
| Team internal invitation | Acceptable if participants are not authors of the scenario |
| Public posting | Possible but screen more carefully for bias |

## Response Handling

When a candidate responds:

1. Send `participant-screening.md` questions
2. Evaluate against inclusion/exclusion criteria
3. If accepted — send `participant-information.md`
4. If rejected — polite decline without revealing reason
5. Log all communication in `participant-communication-log.md`
