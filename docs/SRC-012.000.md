## 2. Scope

The Personal Intelligence Runtime (PIR) is the highest-level orchestration layer in the AIS architecture. It sits above all 8 existing domain Runtimes (Memory, Knowledge, Identity, Capability, Workflow, Cognitive, Experience, Desktop) plus the Platform layer, and unifies their capabilities into a single personal intelligence context that understands the user's goals, habits, attention, learning progress, and daily workflow.

### 2.1 Mandate

- Unify 8 existing Runtimes + Platform into a **personal intelligence layer** that makes intelligent decisions on behalf of the user.
- PIR is **exclusively an orchestration layer**: it makes decisions, generates predictions, tracks habits, and provides recommendations — it does **not** replace any existing runtime.
- All prior Runtime architectures are **immutable** — PIR communicates only through well-defined contract interfaces.
- PIR owns only its derived data (goals, plans, habits, predictions, reflections, decisions, briefs, and metrics). It does not duplicate or cache raw runtime data.

### 2.2 Design Principles

1. **Orchestration Only** — PIR never stores or modifies data belonging to other runtimes. It reads snapshots via contracts and publishes events via the platform event bus.
2. **Contract-Based Integration** — PIR depends exclusively on 9 contract interfaces (`IdentityContract`, `MemoryContract`, `KnowledgeContract`, `WorkflowContract`, `ExperienceContract`, `CognitiveContract`, `CapabilityContract`, `DesktopContract`, `PlatformContract`). It never imports runtime classes directly.
3. **No Data Duplication** — PIR builds lightweight snapshot types (`PersonalContext`, `UnifiedContext`) from runtime data, but does not persist raw runtime state.
4. **Fire-and-Forget Events** — All PIR subsystem events are published asynchronously via `void platform.publishEvent(...)`. The system never blocks on event delivery.
5. **Immutable Data** — All PIR domain objects use `Object.freeze(...)` and `readonly` properties to enforce immutability at the type and runtime level.

### 2.3 Exclusions

This manifest does not cover:
- Individual domain Runtime internals (each has its own SRC manifest)
- UI/UX layer implementation details
- External API gateway configuration
- ML model training or inference pipelines (PIR uses rule-based heuristics)

## 3. Architecture

PIR operates as a **layer above all runtimes**. Its architecture is structured as follows:

```
┌─────────────────────────────────────────────────────────────┐
│                     PersonalRuntime                          │
│  (Orchestrator — creates & wires 15 subsystems + metrics)   │
├─────────────────────────────────────────────────────────────┤
│  UserProfile  │  Goal    │  Priority │  Context │  Planning  │
│  Prediction   │  Habit   │  Recommend│ Atten.   │ Reflection │
│  Learning     │ Decision │  Daily    │ Assistant│  Metrics    │
├─────────────────────────────────────────────────────────────┤
│              PersonalRuntimeContracts (9 contracts)           │
├────────┬────────┬────────┬────────┬─────────┬───────────────┤
│Identity│ Memory │Knowledge│Workflow│Experience│Cognitive│ ... │
├────────┴────────┴────────┴────────┴─────────┴───────────────┤
│                     Platform Runtime                          │
└─────────────────────────────────────────────────────────────┘
```

The `PersonalRuntime` constructor accepts a `PersonalRuntimeContracts` bundle and a `PersonalRuntimeConfig`, then instantiates all 15 subsystems and the metrics collector. It provides:
- `initialize()` — builds the initial user profile and unified context
- `getPersonalContext()` — returns the cached or freshly-built `PersonalContext`
- `getUnifiedContext()` — returns the cached or freshly-built `UnifiedContext`
- `getState()` — returns a frozen summary of all subsystems
- `dispose()` — clears owned maps and resets metrics

## 5. Contracts

PIR communicates with other runtimes exclusively through **9 contract interfaces** defined in `contracts.ts`. No runtime class is ever imported directly.

### 5.1 Contract Table

| # | Contract | Interface | Purpose |
|---|---|---|---|
| 1 | **Identity** | `IdentityContract` | Read user identity: current user, roles, preferences, preference resolution |
| 2 | **Memory** | `MemoryContract` | Read/write memory entries: retrieve, store, query, session/working entries |
| 3 | **Knowledge** | `KnowledgeContract` | Read knowledge base: search, namespaces, item count, recent items, tag queries |

| 5 | **Experience** | `ExperienceContract` | Read experience data: active adaptations, recommendations, current phase, behavior patterns |
| 6 | **Cognitive** | `CognitiveContract` | Read conversation state: current intent, turn count, session ID, summary |
| 7 | **Capability** | `CapabilityContract` | Read capability state: active packs, available capability names |
| 8 | **Desktop** | `DesktopContract` | Read desktop state: open window count, active window, desktop state, subsystem count |
| 9 | **Platform** | `PlatformContract` | Platform services: event publishing, configuration access, health status |

All 9 contracts are bundled into a single `PersonalRuntimeContracts` object that is passed to the `PersonalRuntime` constructor and propagated to all subsystems.
