## 2. Scope

The Universal AI Provider Runtime (AI-PR) is a provider-agnostic execution layer that abstracts all AI model interactions behind a unified interface. It manages provider lifecycle, model routing, request execution, streaming, token budgeting, cost tracking, retry/failover, caching, privacy enforcement, tool invocation, metrics collection, and distributed tracing across 15 coordinated subsystems.

### 2.1 Mandate

- AIS never knows which model answers — it works with the abstraction "AI Model".
- All provider-specific logic is encapsulated behind the `ProviderSDK` interface.
- The runtime orchestrates 15 subsystems through dependency injection, not direct coupling.
- Every subsystem is independently testable with mock dependencies.

### 2.2 Design Principles

1. **Provider-Agnostic** — No provider-specific code exists outside the SDK layer. The runtime routes, executes, and manages without knowledge of OpenAI, Anthropic, Google, or any other provider.
2. **SOLID** — Single responsibility per subsystem, open/closed via `ProviderSDK` abstraction, Liskov substitution via `BaseProviderSDK`, interface segregation via 18 contract interfaces, dependency inversion via constructor injection.
3. **DDD** — Branded identifiers (`ProviderId`, `ModelId`, `ExecutionId`), domain events (31 event types), domain errors (33 error classes), immutable value objects (`Object.freeze`).
4. **Event-Driven** — All state changes emit domain events via `InProcessEventBus`. Subsystems react to events; the orchestrator never polls.
